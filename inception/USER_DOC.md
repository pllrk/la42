# User documentation

## What the stack provides

Starting the project brings up a WordPress website served over HTTPS.

* **nginx** — the only door into the infrastructure. Listens on port 443 with
  TLS 1.2/1.3, serves static files and forwards PHP requests to WordPress.
* **wordpress** — WordPress with php-fpm. Not reachable from outside.
* **mariadb** — the database. Not reachable from outside.

## Starting and stopping

All commands are run from the root of the repository.

| Action                                    | Command        |
|-------------------------------------------|----------------|
| Build the images and start everything     | `make`         |
| Stop the containers (keeps data)          | `make down`    |
| Pause without removing containers         | `make stop`    |
| Resume paused containers                  | `make start`   |
| Rebuild from scratch                      | `make re`      |
| Delete containers **and all data**        | `make fclean`  |

The first `make` takes several minutes: it downloads the Debian base image,
installs packages, and WordPress installs itself on first boot. Later starts
take seconds.

`make fclean` is destructive — it removes the volumes, so the database and the
site content are permanently lost.

## Accessing the site

The domain must resolve to the VM. Run once:

```sh
make host      # appends "127.0.0.1 plerick.42.fr" to /etc/hosts
```

* Website: <https://plerick.42.fr>
* Administration panel: <https://plerick.42.fr/wp-admin>

The certificate is self-signed, so the browser shows a warning the first time.
That is expected; accept it and continue.

`http://plerick.42.fr` will not work — nothing listens on port 80. This is
intentional.

## Credentials

No password is stored in the repository. They live in the gitignored `secrets/`
directory, one value per file, generated by `make secrets` on first run:

| File                             | What it is                          |
|----------------------------------|-------------------------------------|
| `secrets/db_root_password.txt`   | MariaDB `root` password             |
| `secrets/db_password.txt`        | MariaDB password for the WP user    |
| `secrets/credentials.txt`        | WordPress admin and author passwords|

Read the WordPress logins with:

```sh
cat secrets/credentials.txt
grep -E 'WP_ADMIN_USER|WP_USER' srcs/.env
```

To change a password, edit the file and run `make re`. Note that this rebuilds
from scratch — for the WordPress accounts it is gentler to change the password
from the admin dashboard instead.

## Checking that everything runs

```sh
make ps                                   # all three should be Up
docker compose -f srcs/docker-compose.yml logs nginx
```

Targeted checks:

```sh
# TLS version actually negotiated
openssl s_client -connect plerick.42.fr:443 -tls1_2 </dev/null | grep Protocol

# TLS 1.0 must be REFUSED
openssl s_client -connect plerick.42.fr:443 -tls1 </dev/null

# port 80 must be closed
curl -I http://plerick.42.fr

# the site answers
curl -kI https://plerick.42.fr

# the volumes exist and point at /home/plerick/data
docker volume ls
docker volume inspect inception_wordpress_data
```

## If something is wrong

| Symptom                        | Where to look                                   |
|--------------------------------|-------------------------------------------------|
| Browser cannot resolve the name| `grep 42.fr /etc/hosts`                         |
| 502 Bad Gateway                | `docker logs wordpress` — php-fpm probably died |
| "Error establishing a DB connection" | `docker logs mariadb`                     |
| A container keeps restarting   | `docker logs <name>` shows the crash reason     |
